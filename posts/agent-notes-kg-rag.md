# 智能体不是聊天框，而是一套行动系统

很多 Agent demo 看起来像是一个更会聊天的窗口，但我更愿意把智能体理解成一套行动系统：它需要知道目标、调用工具、管理上下文、检查结果，并在必要时把问题重新拆开。

## 我关心的几个模块

- 任务边界：Agent 应该知道自己能做什么，也要知道什么时候该停下来问人。
- 知识来源：RAG 解决动态知识，知识图谱适合承载结构化概念和关系。
- 工具调用：工具不是越多越好，关键是接口稳定、反馈清楚、失败可恢复。
- 评测闭环：没有评测的 Agent 很容易停留在「看起来能跑」。

## 知识图谱的价值

在医疗场景里，概念之间的关系经常比单个片段更重要。疾病、症状、检查、诊疗规则和指南之间存在明确结构，知识图谱可以为 Agent 提供一个可追踪、可解释的骨架。

LLM 擅长语言理解和生成，KG 擅长约束、关系和推理。两者结合时，重点不是把所有东西塞进 prompt，而是设计一条可靠路径：检索什么、对齐什么、推理什么、由谁来验证。

这也是我会持续记录的方向：让智能体从「会回答」走向「能协作完成任务」。
